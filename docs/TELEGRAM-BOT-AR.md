# بوت Telegram — دليل التشغيل

بوت واحد داخل Telegram يعمل كمركز قيادة المتجر: طلبات، تغيير حالات، بحث، عملاء،
مخزون، تقارير، موافقات وتنبيهات — كلها بأزرار داخل المحادثة، بثلاث لغات
(العربية، الفرنسية، الإنجليزية) واتجاه RTL/LTR تلقائي.

> هذا المستند يصف **ما تم تنفيذه فعلياً**. الكتالوج الأصلي وأولوياته في
> [`TELEGRAM-BOT-FEATURES-AR.md`](./TELEGRAM-BOT-FEATURES-AR.md).

---

## 1) التهيئة لأول مرة

1. أنشئ بوتاً عبر `@BotFather` وخُذ الرمز.
2. من اللوحة: **الإعدادات ← Telegram** — ضع رمز البوت ومعرّف محادثة المسؤول.
3. تأكد من ضبط `WORKER_SELF_URL` (أصل عام للـ Worker) — يُستخدم لتسجيل
   الـ Webhook على `POST /webhooks/telegram` وتوليد روابط الدخول المباشرة.
4. عند الحفظ يستدعي الخادم `setWebhook` (مع `secret_token`) ثم `setMyCommands`
   لثلاث لغات، فتظهر قائمة الأوامر داخل Telegram لكل مستخدم بلغته.
5. من صفحة **Telegram** في اللوحة (`/telegram`) ولّد **رمز ربط** لعضو، وأرسل له
   الرمز أو الرابط المباشر. العضو يرسل `/link CODE` أو يضغط الرابط.

الربط لا يشارك رمز البوت مع أحد: كل عضو يربط حسابه بنفسه، والرمز لمرة واحدة
وينتهي بعد المدة المختارة (15 دقيقة / ساعة / 24 ساعة).

### متغيّرات البيئة

| المتغيّر | الاستخدام |
|---|---|
| `TELEGRAM_BOT_TOKEN` | رمز البوت (بديل عن إعدادات اللوحة) |
| `TELEGRAM_ADMIN_CHAT_ID` | محادثة المسؤول الاحتياطية |
| `TELEGRAM_WEBHOOK_SECRET` | سر التحقق من الـ Webhook (يُولَّد تلقائياً عند التسجيل) |
| `WORKER_SELF_URL` | أصل الـ Worker العام لتسجيل الـ Webhook |

## 2) التفاعل: قائمة ← نتيجة ← إجراء ← تأكيد

الشكل واحد في كل الشاشات:

```
رسالة واحدة تتحدّث في مكانها (لا سيل من الرسائل)
├── رأس: القسم + الفترة/المرشّح
├── المحتوى: قائمة مختصرة أو بطاقة تفصيلية
└── أزرار أسفل المحتوى: إجراءات السياق + التنقل (رجوع / القائمة / تحديث)
```

- الانتقال بين الحالات يعدّل نفس الرسالة (`editMessageText`) فيبقى السجل نظيفاً.
- كل إجراء حسّاس يطلب تأكيداً صريحاً (`✅ تأكيد` / `↩️ إلغاء`).
- بعد التنفيذ تُعاد الرسالة محدّثة بالحالة الجديدة، ويُسجَّل الإجراء في
  `telegram_bot_events` لمن لديه صلاحية العرض.

## 3) القائمة الرئيسية

| الزر | ماذا يفعل |
|---|---|
| 📦 **الطلبات** | مرشّحات (جديدة، مؤكدة، قيد التحضير، جاهزة، قيد التوصيل، مسلّمة، مرتجعة…) + آخر الطلبات |
| 📊 **التقارير** | تقرير اليوم، أمس، آخر 7 أيام، آخر 30 يوماً، هذا الشهر، الشهر الماضي + تقارير المخزون والمالية والفريق والعملاء |
| ✅ **الموافقات** | صندوق الموافقات المعلّقة مع أزرار الموافقة/الرفض/التفاصيل |
| 🔔 **التنبيهات** | تشغيل/إيقاف كل نوع تنبيه، ووضع الملخص (فوري / كل ساعة / يومي) |
| 📦 **المخزون** | أصناف منخفضة/نافدة وتعديل سريع |
| 🔎 **بحث/إعدادات** | بحث بالرقم/الهاتف/اسم العميل، وبطاقة العميل، واللغة، وساعات الهدوء |

الأزرار تُبنى حسب صلاحيات العضو: من لا يملك نطاقاً لا يرى زرّه، ومن يحاول
استدعاءً ممنوعاً يحصل على «غير مصرّح» مسجّلة في السجل.

## 4) الطلبات والحالات

عند فتح «طلبات» تظهر قائمة بالنتائج (مع أرقام الصفحات). تحت كل طلب أو في
بطاقته تظهر أزرار الحالات **المسموحة فقط** حسب خريطة الانتقالات:

```
new → confirmed | unreachable | cancelled
confirmed → preparing | unreachable | cancelled
unreachable → confirmed | cancelled
preparing → ready | cancelled
ready | assigned → out_for_delivery | dispatched | cancelled
dispatched → out_for_delivery | cancelled
out_for_delivery → delivered | returned
delivered | returned | cancelled → (نهائي)
```

- تغيير الحالة يمرّ عبر `updateOrderStatus` نفسها المستخدمة في اللوحة:
  تحديث قاعدة البيانات + منع التكرار (idempotency) + سجل النشاط + خطّافات
  CAPI Meta + المسارات اللاحقة (إرجاع المخزون، رصيد السائق…).
- الحالات الحسّاسة (مثل الاسترجاع/الإلغاء بعد التأكيد) تمرّ عبر
  **طلب موافقة** إن كانت سياسة المتجر تطلب ذلك، وتُبلَّغ في Telegram مع أزرار.
- «📞 نسخ الهاتف» يضع الرقم في الحافظة بضغطة واحدة.
- من صفحة الطلب يمكن تعديل: حالة الطلب، تعيين موظف تأكيد/سائق (حسب النطاق).

---

## 5) الموافقات

- ينشئ النظام طلب موافقة عند: تغيير حالة حسّاسة، استرجاع طلب، صرف عمولات.
- تُرسل بطاقة إلى المسؤولين المعنيّين: العنوان، السبب، البيانات، مدة الصلاحية.
- الأزرار: `✅ موافقة` / `❌ رفض` / `👁 التفاصيل`. القرار **idempotent**:
  طلب واحد يُنفَّذ مرة واحدة، وطلبات منتهية الصلاحية تُرفض بأمان.
- بعد القرار يُبلَّغ مقدّم الطلب، ويُنفَّذ الإجراء المصرّح به فقط
  (`mark_commissions_paid`, `orders.status_change`, `orders.return`).
- تذكير تلقائي قبل انتهاء المهلة، وتصعيد للمسؤول عند تجاوزها
  (`reminder_sent_at` / `escalated_at` في `admin_approval_requests`).

## 6) التقارير

| التقرير | المحتوى |
|---|---|
| ملخّص الفترة | عدد الطلبات، المؤكدة، المسلّمة، المرتجعة، نسبة التأكيد، الإيرادات، متوسط السلة |
| المخزون | أصناف تحت الحد الأدنى، نافدة، قيمة المخزون |
| المالية | الإيرادات، تكاليف التوصيل، العمولات، صافي الربح التقريبي |
| الفريق | إنتاجية كل موظف تأكيد/سائق ونسب النجاح |
| العملاء | الأكثر شراءً، عملاء جدد/عائدون، أعلى الولايات |

- تُبنى من نفس استعلامات اللوحة (`getAnalyticsOverview`, `getProfitAndLoss`,
  `getProductAnalytics`, `getWilayaAnalytics`)، فلا تختلف الأرقام بين الاثنين.
- تقرير يومي مجدول + تقرير أسبوعي/شهري اختياري من إعدادات البوت.
- توقيت الإرسال يُحسب بـ `localClock(now, timezone)` لا بتوقيت UTC.

## 7) التنبيهات

- **فورية:** طلب جديد، فشل تكامل حرج، نقص مخزون حاد.
- **غير حرجة:** تُحترم ساعات الهدوء ووضع الصامت، وتُجمع في طابور
  (`telegram_bot_digest_queue`) ثم تُرسل كملخص واحد حسب الفاصل المضبوط.
- كل نوع تنبيه يُفتح/يُغلق من زر «التنبيهات» داخل البوت، أو من صفحة Telegram
  في اللوحة.
- منع التكرار عبر `shouldSendAlert` + `markAlertSent` بمفتاح فريد لكل حدث،
  وهو ما يمنع «عاصفة رسائل» عند تزامن الطلبات أو ساعات الذروة.

## 8) الصلاحيات والنطاقات

| الدور | يرى | يستطيع |
|---|---|---|
| مدير | كل شيء | كل الإجراءات، الموافقات، إعدادات البوت |
| موظف | حسب نطاقاته | الطلبات/التقارير المطابقة لنطاقه |
| مؤكد طلبات | طلباته | تأكيد، تعذّر الوصول، إلغاء قبل التحضير |
| سائق | توصيلاته | بدء التوصيل، تسليم، إرجاع |

- يحتفظ البوت بمعرّف Telegram فقط؛ لا كلمات مرور ولا رموز داخل المحادثة.
- كل إجراء يُسجَّل: من، ماذا، على أي طلب، والنتيجة (نجاح/مرفوض/فشل).
- سرّ الـ Webhook يُتحقَّق منه في كل طلب (`X-Telegram-Bot-Api-Secret-Token`)،
  وتُهمَل التحديثات المكرّرة عبر `telegram_update_log`.

## 10) لوحة التحكم

صفحة `/telegram` (للمدير) تعرض:

- حالة الاتصال ومصدر الإعدادات وعنوان الـ Webhook.
- بطاقات: الحسابات المرتبطة، الموافقات المعلّقة، عدد الإجراءات المسجّلة.
- توليد رمز ربط (مع رابط `t.me/...?start=CODE`) ونسخه.
- جدول الحسابات المرتبطة: العضو، الحساب، اللغة، وضع التنبيهات، آخر نشاط،
  إرسال رسالة تجريبية، وإلغاء الربط.
- صندوق الموافقات (نفس الطلبات التي تصل البوت) مع قرار مباشر وملاحظة.
- إعدادات البوت: التفعيل، اللغة، ساعات الهدوء، فاصل الملخص، التقرير الأسبوعي
  والشهري.
- سجل نشاط البوت.

### واجهات الخادم

| المسار | الوظيفة |
|---|---|
| `POST /webhooks/telegram` | استقبال تحديثات Telegram (خارج المصادقة، محمي بالسر) |
| `GET /api/operations/telegram/bot/overview` | حالة البوت + الروابط + السجل + الموافقات |
| `PUT /api/operations/telegram/bot/config` | تحديث إعدادات البوت |
| `POST /api/operations/telegram/bot/link-codes` | توليد رمز ربط |
| `DELETE /api/operations/telegram/bot/links/:id` | إلغاء ربط عضو |
| `POST /api/operations/telegram/bot/test` | رسالة تجريبية |
| `GET /api/operations/approvals` | قائمة الموافقات |
| `POST /api/operations/approvals/:id/decision` | قرار موافقة/رفض |

> ملاحظة: العمليات المستخدمة في التقارير هي نفسها المستخدمة في اللوحة، ونفس
> صلاحيات النطاقات (RBAC) تُطبَّق في واجهات الـ API والبوت معاً.

## 11) الجدولة (Cron)

`runTelegramBotMaintenance` يعمل ضمن `scheduled()` كل 15 دقيقة:

1. تذكير/تصعيد الموافقات المعلّقة.
2. مسح التنبيهات (`runAlertScan`).
3. إرسال الملخصات المستحقة (`flushDigests`).
4. التقارير المجدولة (`sendScheduledReports`).
5. تنظيف سجلات الـ Webhook/التحديثات القديمة (`pruneBotHousekeeping`).

كل خطوة في `try/catch` مستقل، فلا يُسقِط فشلُ إحداها الباقي.
